# ADR-001: Use C++20 Standard

## Status
✅ Accepted

## Context
Unreal Engine 5.8 supports C++20. The project needs modern C++ features for cleaner, safer, and more performant code. Previous projects used C++17.

## Decision
Adopt C++20 as the standard for all C++ code in the DA Framework.

## Consequences

### Positive
- **Modules** (when UE supports): Better encapsulation, faster compiles
- **Concepts**: Constrain templates, better error messages
- **Ranges**: Composable algorithms, less boilerplate
- **Coroutines**: Async/await patterns for latent operations
- **`std::format`**: Type-safe formatting (UE has `FString::Format` but std is standard)
- **`std::span`**: Non-owning views over contiguous data
- **`constexpr` improvements**: More compile-time computation
- **Structured bindings**: Cleaner tuple/struct decomposition
- **`[[nodiscard]]`, `[[likely]]`, `[[unlikely]]`**: Better optimization hints

### Negative
- **Compiler support**: Must ensure all target compilers support used features
- **UE version lock**: Requires UE 5.1+ for full support
- **Learning curve**: Team must learn new features
- **Static analysis**: Tools must support C++20

### Neutral
- **Standard library**: UE uses its own containers (`TArray`, `TMap`, etc.) — std features complement, not replace

## Alternatives Considered
- **C++17**: Stable, well-supported, but missing modern features
- **C++23**: Too new, not supported by UE 5.8 toolchain
